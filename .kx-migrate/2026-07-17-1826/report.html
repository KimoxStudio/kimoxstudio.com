Framework observations (F1–F7)

F1 · localization has no store/switcher or locale-aware preview

mediumframework-limit

The framework does ship localized()/localizedList()/resolveLocalized() (@kx/registry) and createClientStore() (@kx/renderer/client) — those made the migration clean. What's still missing: a built-in language store + switcher, and a locale-aware admin preview. Each localized site must hand-wire its own lang store (here: kx/stores.ts + a rewritten lib/lang.js) and the admin shows all N language fields per text with no active-locale preview.

F2 · collection-list derives from single-language meta only

mediummissing-props

collection-list auto-derives rows from docs under a route prefix, reading each doc's meta.title/description — single-language, and with no featured/category facets. The trilingual blog with a featured split + client category filter can't use it losslessly, so /blog stayed an island. A localized-meta source + facet options would unblock it.

F3 · prose takes one markdown string, no localized variant

mediummissing-props

The prose template renders a single markdown body. The blog posts carry {es,en,ja} markdown bodies; without a localized-markdown prop they can't be represented in a document, so posts stayed islands. A localizedMarkdown field (resolve-then-render) would let posts migrate.

F5 · admin base path collides with an existing /admin; not configurable

mediumframework-limit

The chassis convention mounts the admin at /admin, which collides with the site's existing Decap CMS. There's no documented admin-base-path config; the migration mounted the SPA at /kx-admin manually (the API stays at /api/kx/*, which the admin client hardcodes — that part was fine). A first-class base-path option would remove the manual step.

F4 · page chrome:"none" still emits a <main> wrapper

lowframework-limit

The stock page template's chrome:"none" renders a bare <main>. A site whose original markup had no wrapper element (sections directly under body, fixed nav) needs the component overridden to a fragment (done here). A chrome:"bare" fragment mode would avoid the per-site override.

F6 · document meta not surfaced to generateMetadata

lowmissing-props

renderPageFromContent exposes no way to read a loaded document's meta, so the catch-all can't set per-page <title>/description from the document — the root layout's metadata is the only lever. Fine here (layout title is correct) but a blocker for multi-page sites with distinct titles.

F7 · @kx peers are ^14||^15; Next 16 needs --webpack

lowframework-limit

@kx/nextjs declares peer next ^14||^15. On Next 16 the app builds/runs only with --webpack (Turbopack can't resolve link: deps), and middleware.ts warns (deprecated for proxy.ts). Both are handled (scripts pinned to webpack; warning noted) but the peer range and a proxy story should be updated.

Decisions & caveats

  • i18n strategy 1 (localized-leaf). Chose the switcher-preserving path: {es,en,ja} props via the framework's localized helpers, resolved with the active language. Rebuilt lib/lang.js's useLang over a shared external store (kx/stores.ts · createClientStore) so the nav switcher drives every independently-mounted section — the classic "useState trap" the skill warns about. Verified live: ES→EN→JA switches all sections.
  • Content transcribed verbatim. content/pages/index.json was generated from the real I18N object (a one-off script) — no manual retyping, so the diff is a pure re-homing of content, typos and all. lib/i18n.js is retained (the blog island's Nav still reads I.nav/I.meta); the landing keys are now duplicated into the document.
  • Decap CMS kept; kx admin at /kx-admin. Decap still edits the island blog markdown, so it was not removed. Log in to the kx admin with admin/admin (defaults; override via KX_ADMIN_*).
  • Stub git provider (in-memory, seeded from disk). The admin reads/writes in process memory; content/ files on disk are the source of truth and win after a dev restart. Publishing a variation does not write back to disk — swap createStubGitProvider for createGitHubProvider for production persistence.
  • zod 4 → 3. Downgraded to zod ^3.23 for the admin's AutoForm (v3 _def introspection). The project's only zod call site (contact.js) already used v3-compatible spelling — no code changes.
  • Env vars to set for production: KX_ADMIN_USER/PASSWORD, KX_SESSION_SECRET, KX_COOKIE_SECRET (kx admin); existing RESEND_*, UPSTASH_*, STUDIO_* unchanged. All documented in .env.example; no real secrets written.
